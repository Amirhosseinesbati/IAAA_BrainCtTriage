# Competition pipeline implementation report

## Objective

The implementation aligns model development with study-level Macro-F1 after
the official seven intermediate quantities are converted by the fixed triage
rule. It does not claim a new leaderboard score: models must first be trained
for every patient-grouped fold and produce genuine OOF predictions.

## Source control

The previous MLS feature history and outstanding submission package changes
were squashed into local `develop`. Work continues on
`codex/competition-winning-pipeline` with one focused commit per subsystem.

## Configuration

`config/project.yaml` owns all project paths, label maps, CT windows, official
thresholds, MLflow experiment names, artifact paths, training defaults,
post-processing and Vast.ai hardware profiles. `src/config.py` is a backwards
compatible loader rather than a second source of defaults.

## Leakage-free evaluation

`config/folds.csv` contains 338 studies from 320 patients across five folds.
Every patient is assigned to exactly one fold. Fold class counts are balanced:

| fold | class 0 | class 1 | class 2 | total |
|---:|---:|---:|---:|---:|
| 0 | 34 | 12 | 24 | 70 |
| 1 | 33 | 12 | 22 | 67 |
| 2 | 33 | 12 | 22 | 67 |
| 3 | 32 | 12 | 22 | 66 |
| 4 | 33 | 12 | 23 | 68 |

The evaluator reports Macro-F1 as the official guide metric, QWK as a
secondary metric, per-class metrics, catastrophic 0-to-2/2-to-0 errors and a
patient-bootstrap confidence interval. Error tables record the first triage
rule activated and signed distance to each decision boundary.

The manifest is no longer documentation-only. The active MONAI SegResNet,
YOLO fracture, and MLS heatmap loaders all resolve their validation studies
from this same file. Unknown studies, empty partitions and fold mismatches
fail before training. Fold-specific YOLO datasets use separate directories so
one fold cannot silently reuse another fold's split.

## Active strategy policy

The project intentionally exposes one submission-compatible path per task:

- ICH: MONAI 3D SegResNet;
- fracture: YOLO box detector;
- MLS: HRNet heatmap keypoints with DARK decoding.

nnU-Net is not installed in the official runtime. SMP and YOLO segmentation
had no OOF evidence strong enough to justify parallel maintenance. The legacy
MLS selector/direct-coordinate pipeline was also removed; heatmap confidence
now performs candidate-slice selection. HRNet W18/W32 remain capacity settings
inside the same MLS architecture and must be compared through the shared OOF
protocol rather than presented as separate strategies.

`scripts/assemble_oof.py` defines the join boundary between the three tasks.
It requires exactly one prediction for every study from each task, validates
reported fold IDs, rejects duplicates/non-finite values, reconstructs the
seven ground-truth intermediates in physical units, and emits the only
combined CSV accepted by evaluation/calibration.

## Competition-aware model objective

MLS validation now uses each sample's real DICOM `PixelSpacing`, including an
in-memory metadata upgrade path for older processed CSVs. The former fixed
0.5 mm/px approximation has been removed. MLS heatmap training retains masked
heatmap MSE and adds two configurable auxiliary terms:

- differentiable Smooth-L1 on the final MLS value in millimetres;
- ordinal boundary loss at the official 1/3/5 mm decision points.

All three loss terms are logged separately to MLflow. Setting their auxiliary
weights to zero provides a controlled MSE-only ablation from the same UI.

## Calibration and post-processing

The calibration bundle fits a monotonic isotonic mapping for each intermediate
quantity. Its reported score is generated by nested folds: each fold is
transformed only by a calibrator fitted on the other folds. The final compact
JSON is fitted only after this check. A candidate is promoted to the configured
model path only if its nested-OOF Macro-F1 gain, paired patient-bootstrap
probability of improvement, and catastrophic-error count satisfy the YAML
policy. Rejected candidates remain in the report directory for audit and
cannot silently replace an accepted bundle. Physical cleanup removes 3D ICH connected
components by millilitre volume, not raw voxel count. Outputs are finite,
non-negative and clipped to physical ranges.

## MLOps and MLflow

Each task/strategy has a stable experiment name. Every training attempt creates
one run containing:

- flattened parameters and the exact resolved run YAML;
- the complete central project YAML;
- run notes, tags, git commit/branch/dirty state;
- Python, platform, Torch, CUDA and GPU metadata;
- system metrics where supported;
- best/final checkpoints, plots, logs and a machine-readable summary;
- a source snapshot of `src`, `config`, `scripts`, `setup_vast.sh`,
  `pyproject.toml` and `uv.lock`.

Lightning and Ultralytics duplicate MLflow runs were removed. Their output is
attached to the single owned run.

## UI and Vast.ai

The Streamlit control center builds one versioned `ExperimentManifest`. It
controls task/strategy configuration, run identity, notes/tags, GPU, disk,
price range, download-speed range, effective CPU-core range, reliability, Git
branch, preprocessing reuse and auto-destroy. By default the cheapest matching
offer is selected. The optional Top-K mode instead evaluates only the K cheapest
matching offers and chooses the strongest Vast score/value candidate (then
reliability and price as tie-breakers).
The manifest can be previewed, downloaded, saved, price-checked with a dry run
or launched.

The UI can expand any task configuration into a validated five-fold suite.
Each generated run has a distinct run name, fold config and MLflow fold/suite
tags. Saving a suite is bulk; paid Vast launches remain explicit per manifest.

Vast.ai uses argument lists rather than `shell=True`, filters offers before
renting, never prints secrets, clones the exact branch, installs the lockfile,
pulls DVC data and passes the unchanged manifest to the pipeline. Auto-destroy
runs after success and failure.

## Submission

The package has its own `submission/config/inference.yaml`. It supports
physical component cleanup and an optional OOF-approved calibration JSON. If
the bundle is absent, only deterministic physical sanitization is applied. The
ZIP builder enforces the configured one-gigabyte limit and removes the output
if the limit is exceeded.

Current verified ZIP: 349.6 MiB, 10 files, integrity check passed, 34.1% of the
configured limit.

- 72 unit/integration tests pass, including split parity, nnU-Net translation,
  physical spacing, differentiable MLS loss, OOF coverage and calibration
  acceptance.
- Python compilation, Bash syntax, Streamlit health, manifest round-trip and
  submission ZIP integrity checks pass.
- The last verified submission ZIP is 349.6 MiB (34.1% of the 1 GiB limit).
- No paid Vast instance was created, no branch was pushed, and no new GPU
  five-fold training was run in this local implementation phase. Therefore no
  new leaderboard score is claimed; 0.914491 remains a target, not a measured
  result of these code changes.
